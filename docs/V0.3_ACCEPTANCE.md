# v0.3 修正与动态叙事增强 — 完成报告

对应 `After_the_Bell_CodingAgent_修正与动态叙事增强任务_v0.3.md`。
基于现有代码增量修改，保留 Ren'Py + FastAPI + HTTP/JSON + SQLite、三种结局、无 SSE。

## 1. 逐项完成情况

### P0-1 语义正确性（已完成）

- `rules/meaningful_turn.py` 重写为**小句级解析**：
  - 引号内容整体剔除（引用别人的话不产生玩家动作）；
  - 每条动作在所属小句里检查：主语（我/你/他/陈屿）、否定（不/没/别/不要，且排除「是不是/不错/差不多」等假否定）、
    疑问、假设（如果/要是/就算）、对象（「我喜欢陈屿」不算向许栀表白）；
  - 高影响动作（表白/控制/支持自主/解释/承诺）必须由规则确认；模型只能补 `care/ask_distance/ask_chenyu/small_talk` 这类低风险动作。
- 事实闸门：`support_autonomy` 不再直接写 `class_change_discussed`；该事实只由「真的谈过分班计划与未来」的
  `discuss_class_future` 动作或 `class_choice` 事件结算写入。
- 新增 `reject_romance` / `choose_friends` 动作与 `player_declined_romance` / `player_chose_friends` 事实。
- 回归测试：`tests/test_semantics.py`（文本层 + `/interact` 状态层共 19 项），覆盖文档给出的 8 个反例。

### P0-2 Storylet 生命周期（已完成）

- 新增 `rules/storylet_progress.py`：
  - 生命周期 `active → interacting → resolved / abandoned`，状态字段 `storylet_stage/evidence/turns/resolved_storylets/abandoned_storylets`；
  - 每个事件有初始证据与专属评估器；证据不足 → `pending` 继续等待；超过最大轮数或场景变化 → `abandoned`（不写任何事实）；
  - 所有效果只应用一次（`resolved_storylets` 去重），重试不会重复加值。
- `walk_home`：只有明确接受同行才写 `walk_home_done`；拒绝/各自离开不写。
- `class_choice`：必须同时谈「分班计划」和「之后怎么相处」，只问候/只表态支持都不算。
- `late_explanation`：区分 `misunderstanding_discussed` 与 `misunderstanding_resolved`；澄清需要
  「解释 + 那句话进入讨论 + trust≥42 + respect≥40」，且证据足够时不允许模型降级成「只说开一半」。
- 回归测试：`tests/test_storylet_lifecycle.py`（10 项）。

### P0-3 读档时间线（已完成）

- 引入 `branch_id`：状态、turns、memories、events、requests、llm_calls 全部带分支；
  `requests` 主键迁移为 `(game_id, branch_id, request_id)`，旧库自动迁移到 `main`。
- `restore(version)` 不再覆盖当前分支，而是**新开分支**：
  - 清空 `active/scheduled/storylet_stage/evidence/last_plan_turn`；
  - 只把读档点之前的 turns/memories/events 复制进新分支；
  - 后续读写、记忆召回、导演上下文全部只看新分支。
- 回归测试：`tests/test_timeline.py`（5 项），包括旧库迁移。

### P1-1 NPC 主动行为（已完成，LLM 模式）

- Character Agent 输出新增 `npc_intent`（`rules/npc_intents.py` 白名单 + 上下文校验）。
- 她可以主动：问疏远、提分班、邀请同行、提共同记忆、划边界、放下话题。
- 引擎只把它变成**排期**（`kind=npc` 事件），不直接提交事实；限制频率（≥2 回合）与上下文（如只在
  校门口邀请同行、信任≥40）。
- **导演负责"现在适合推进哪类矛盾"，她负责"愿不愿意/怎么开口"**：意图与导演建议冲突时，排期以她的意愿为准。
- Mock 模式不产生主动意图（保持确定性测试）；LLM 模式有效。

### P1-2 open_threads（已完成）

- `rules/threads.py` 管理三条线索：`distance_between_us` / `misunderstanding_quote` / `class_change_future`。
- 状态**只从 facts / 关系值推导**（单一事实来源），变化时记录 `evidence`（版本、回合、原因）；结局时未解决线索
  统一收为 `unresolved/deferred`。
- 导演 prompt 增加「未解决的线索」，确定性打分对相关目标加权。

### P1-3 可验证的灵活结果（已完成）

- 每个事件由「语义证据 + 当前阶段 + 双方行为」计算 `allowed_outcomes`：
  - 证据不足 → `pending`；
  - 证据足够 → 模型可在允许集合里选择（例如同行事件可区分「一起聊天」与「只是同行」）；
  - 关键结果（澄清）证据足够时只有唯一合法结果，防止模型降级。
- 事件日志记录 `outcome / reason / evidence / proposed_outcome`，可复盘"为什么这样判定"。

### P2-1 目标细化（已完成）

- `content/narrative_goals.json` 增加 `progress_if / done_if / optional / activate_if`，
  `rules/goals.py` **只按 JSON 谓词推进**，删除了 Python 里硬编码的那套条件。
- 新增非必经目标 `repair_or_deepen_trust`：出现控制/信任下滑才激活，关系顺利时标记 `skipped`；
  结局结算时 `skipped` 不会算失败。

### P2-2 两个轻量 Storylet（已完成）

- `unfinished_conversation`（没说完的话）：误会谈过但没解决、或出现控制冲突时触发；
  结果 repaired / partially_understood / worsened / avoided。
- `shared_memory`（你还记得吗）：只有真实共同经历（旧便签/一起走过）之后才可能触发；
  不凭空发明过去；结果 shared_warmth / different_understanding / memory_avoided。
- 两者都自带 `exposition` 背景旁白，并配有建议回复。

### P2-3 结局铺垫（已完成）

- `walk_home` 增加 `walked_and_talked`（同行且真的聊到两个人的事），同行 ≠ 交往。
- `school_gate_finale` 需要关系信号（表态或明确的关系话题）；无关对话会继续等待，第 2 轮仍无信号才收束。
- 结局门槛：
  - `romance` 增加「玩家没有明确拒绝恋爱」；
  - `friends` 允许「玩家选择做朋友」，但尊重值 <30 或她已 `declined` → 只能走 `missed`；
  - 结局文本与本局事实一致（拒绝恋爱不会出现恋爱结局）。

## 4. 兼容性与迁移

- 旧 SQLite 库启动时自动迁移：补 `branch_id`（默认 `main`）、重建 `requests` 主键；旧数据可继续读。
- API 返回结构只增不减：`/state`、`/restore` 增加 `branch_id`；事件新增 `pending/abandoned` 状态；
  `walked_and_talked` 是新结果值，旧客户端按字符串展示不受影响。
- 存档：仍只存 `game_id + state_version`；`/restore` 现在会创建新分支并返回 `branch_id`。

## 5. 剩余风险与后续

1. **语义仍基于规则 + 小句启发式**：反讽、长复句、方言式表达可能漏判；漏判时偏保守（不提交事实）。
2. **NPC 主动意图只在 LLM 模式生效**：Mock 模式为了确定性测试不产生主动行为。
3. **导演仍同步**：关键回合多 1–2 秒。
4. **线索状态由 facts 推导**：如果未来新增事实，需要同步更新 `threads._compute` 的映射。
5. **未做 SSE/Web**；真人 15–20 分钟时长仍未测。
6. `requests` 分支化后旧请求缓存不再跨分支命中；重试同一 `request_id` 会按新分支重新处理（符合"新时间线"预期）。

## 6. v0.3.1 补丁（2026-11-18）

针对试玩中“分班说过又提、回忆旁白硬插、节奏偏短、底部面板混排”的修正：

| 项 | 改法 |
|---|---|
| 分班重复 | 新增 `class_talk` 规则：玩家问分班 + 她说出计划（填了/报理重点班/还不确定）→ 直接写 `class_change_discussed`，`class_choice` 永久关闭；prompt 明确“已经告诉过他，不要再提意向表/反问知不知道” |
| 分班太晚 | `class_choice` 提前到 `meaningful>=3` 可触发，导演打分 +25；玩家先问到时由 `class_talk` 直接落事实，不再演第二遍 |
| 回忆乱插 | `shared_memory` 必须满足 `player_mentioned_memory`（玩家说“记得/以前/那次/便签/上次/回忆”）；cue 按真实锚点变体点名“旧便签”或“一起走的那段路” |
| 回忆空转 | 激活当轮只铺情境；玩家不接时到下一轮才安静放弃，不再“确实一起经历过 + 一件小事 + 轻轻带过去”三连 |
| 事件连播 | 事件刚结束的一轮不排新事件（`last_storylet_resolved_turn`），留一轮呼吸 |
| 节奏偏短 | 默认预算 12 → 14；结局资格要求 `turn_index >= 13`；硬收束按回合数封顶（17），不会无限拖 |
| 面板混排 | 底部拆成旁白页（只显示旁白 + 继续）与对话页（只显示她这一句 + 建议 + 输入框）；完整记录仍在右上角抽屉 |
| 面板过高/忽高忽低 | 固定 236px，旁白页与对话页同高，四周留白；比旧版 322px 低，又不会随文字行数跳动 |
| 提示重复 | 已点过（或手动发过同样文本）的建议写入 `used_suggestions`，后续过滤不再出现；同一轮重复文本也只保留一个 |
| 底部操作/输入 | 「推进时间 / 结束本局」固定到面板最下方动作条；输入框前加「你：」前缀，明确这是玩家在说话 |

验证：

- `pytest`：133 项全过；
- `renpy lint`：0；客户端自检全绿（含旁白页、对话页、记录抽屉、结局卡）；
- 真模型路线：romance 15 回合、friends 15 回合、missed 17 回合；分班只出现一次，回忆事件只在玩家提及时出现。
